# v0.3 behavior baseline and v1 boundary schemas

This baseline is captured on `v0.4-product`. No CDE, Kingpin, gateway, HTTP
payload, or policy implementation changes are part of this step. Schemas are
opt-in descriptions checked in tests, not newly installed runtime validators.
CDE reports deviation and requirements; Kingpin alone decides authority; the
gateway mechanically enforces the decision. Tools remain simulated.

## Observable behavior locked by regression tests

| Behavior | Current contract | Coverage |
| --- | --- | --- |
| Authority progression | Full 7 → non-destructive 4 → read-only 2 → quarantined 0 → 2 → 4 → 7. Contraction is immediate; revision increments on each level transition. | Node: full progression, monotonic contraction |
| Gate 0 | Inactive deviation; PASS, no CDE evidence or lease requirement. Tool floors still apply. | Python: routing boundaries; Node: floors |
| Gate 1 | Active deviation; EVIDENCE REQUIRED. Both `dry_run === true` and non-null `diff` with nonempty `String(diff).trim()` are needed. | Node: evidence artifacts |
| Gate 2 | Active deviation; LEASE REQUIRED. A valid scoped lease is necessary but cannot bypass the envelope. Quarantine reason contracts to zero tools. | Node: contraction and baseline outcomes |
| HUMAN REVIEW | LOW_CONFIDENCE produces Gate 1; Kingpin returns `human_review` even with evidence. Quarantine and out-of-envelope denial have precedence. Gateway returns 428. | Python: confidence precedence; Node: review and precedence; merged demo fixture |
| Tool floors | `fs.list`, `fs.read`: 0; `fs.write`, `git.commit`: 1; `fs.delete`, `shell.rm`, `git.reset_hard`: 2. Effective gate is max(CDE gate, floor). Unknown tools are denied. | Node: all seven floors, unknown tool |
| Lease scope | Evaluated context and currently eligible tool required for issuance. Exact canonical args, tool, session, speaker, channel and selected scope must match. Expiry is exclusive. Duration 0.001–300 seconds. | Node: lease binding, expiry, canonical ordering |
| Envelope dominance | Contraction revokes every lease in that authority context. Issuing or using a lease cannot expand the envelope. | Node: contraction |
| Token / “nonce” revocation | `lease_token` is a random UUID, reusable until expiry/revocation; there is no separate nonce field or one-use lease rule. Revoking a token invalidates only that lease. | Node: token vs capability revocation |
| “Global” revocation | No system-wide revoke operation exists. Revoking a tool removes it and all its leases only in the selected context. Other contexts remain unaffected. CDE's `global` baseline is not a global authority revocation namespace. | Node: scoped revocation and isolation |
| Recovery does not revive grants | Explicitly revoked or contraction-revoked leases stay invalid after recovery. Explicit tool revocations also persist; fresh eligible leases must be issued. | Node: recovery and explicit revocation; merged demo |
| Deterministic restoration | Two distinct consecutive inactive Gate 0 evaluations restore exactly one level. Any active evaluation resets the clean counter. Restoration stops at full; it does not clear revoked tools. | Node: exact counters/revisions, interrupted recovery, identical streams |
| One-use evaluation IDs | The server supplies `top_event.event_id`. Each ID is consumed once per authority context, including blocked outcomes. Reuse throws before a second transition. The same ID in a different context is currently accepted. Invalid signals are rejected before state mutation. | Node: consumed IDs, duplicate recovery, invalid signals |
| Enforcement | allow/constrain/deny/quarantine/human_review → HTTP 200/409/403/423/428. Only allow sets `allow: true`; all others set `blocked: true`. Fields are projected from Kingpin, including legacy aliases. | Node: mechanical enforcement and projections; merged demo |

Authority context is `(session_id, speaker_id, channel_id, scope_key)`. Missing
or null session becomes `default`; scope selects scene, then task, then agent.
CDE signal scope must match. Clean evaluations count regardless of whether the
requested tool is ultimately allowed. State and consumed IDs reset on restart.
The existing 32-event Python golden baseline remains unchanged.

## Versioned boundary fields

The four Draft 2020-12 JSON Schemas live in `schemas/v1/`, each with a stable
`urn:cde-kingpin:v1:<name>` identifier. This is contract version 1, separate from
the product branch version. Signals and decisions retain their existing wire
`schema_version: "1.0"`. Requests and lease responses have no version field;
their version is selected out of band by schema ID. No transport wrapper is added.

| Schema | Chosen fields |
| --- | --- |
| `CDEGovernanceSignal` | `schema_version`, `scope_key`, `deviation` (severity, EMA severity, confidence, active/enter/exit, vector), gate, label, evidence requirements, reason codes, authority requirement/recommendation. Gate-dependent fields must agree. No allow/decision/token fields. |
| `AuthorityRequest` | Existing `Kingpin.decide` request argument: tool, speaker, channel; optional args, session/scene/task, dry_run, diff, lease_token, and known HTTP metadata plan_id/user_request/demo_fixture. Signal and trusted evaluation ID remain separate arguments. |
| `AuthorityDecision` | Version, issuer (`kingpin`), policy version (`demo_v1`), evaluation ID, normalized context, outcome, reason/codes, capability envelope (level, tools, revision, clean counter, restoration interval, revoked tools), CDE/floor/effective gates and label, evidence/missing evidence, authority requirement. |
| `CapabilityLease` | Existing issuance response: lease_token (UUID), lease_id (SHA-256 hex of token), normalized context, expires_at (date-time), issuer (`kingpin`). |

Schemas describe the known JSON boundary shape, not every permissive JavaScript
input. Unknown properties are rejected by these opt-in schemas; the existing
runtime may ignore them. Nothing imports these schemas in production. The
Python contract test validates actual CDE outputs and actual Node Kingpin
outputs, plus negative cases, using a test-only JSON Schema dependency.

## Representation limits retained for a later step

- A lease response is an opaque handle, not a self-contained capability:
  tool, canonical args, expiration milliseconds and revocation reason are held
  in Kingpin's private map. Adding those fields or a wire version would change
  the payload. The schema intentionally describes only the existing response.
- AuthorityRequest is not an HTTP `/tool` schema: HTTP additionally checks
  plan_id and user_request. Runtime allows missing args during evaluation,
  while issuance requires an object. Runtime also accepts some non-object args
  and coerces evidence/duration values. The request schema uses object args
  for the known boundary, leaves evidence unconstrained, and does not claim to
  capture every JavaScript coercion or context normalization rule.
- One-use IDs, envelope history, canonical argument equality, expiry, revocation,
  and decision precedence require stateful code/tests. JSON Schema cannot
  authenticate the issuer, prove provenance, or enforce those temporal rules.
  Decision cross-field policy remains owned by Kingpin, not duplicated here.
- CDE's existing Pydantic model is more permissive than Kingpin's signal
  validator (for example numeric ranges); the boundary schema describes the
  valid exchange, without replacing either validator. Audit provenance lives
  beside the signal in the event/response, not inside the signal.
- There is no global revocation or independent nonce mechanism to model.
  Introducing either would be new behavior and is deferred.

## Reproduce validation

```sh
python -m pip install -r requirements.txt -r requirements_gateway.txt -r requirements_test.txt
python -m unittest discover -s tests -v
npm --prefix gateway_node test
CDE_PYTHON="$(command -v python)" npm --prefix gateway_node run demo
python run_demo.py
```

The merged demo requires permission to bind loopback ports 8008 and 8787.

Validation recorded for this change: Python unittest **7 passed**, Node test
runner **20 passed**, no failures or skips. This includes **3 new Python tests**
and **6 new Node tests**. All merged-demo assertions passed, including HTTP 428,
contraction/recovery and fresh issuance after revocation. Standalone CDE demo
completed successfully. `git diff --check` passed. The initial sandboxed merged
run could not bind loopback ports; the permitted rerun passed. No runtime source
files or existing golden fixture were modified.
